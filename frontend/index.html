ADSA: Divide and Conquer Zone Partitioning

Demonstration of the Divide-and-Conquer algorithmic paradigm. The microgrid divides the set of all zones recursively into balanced regional control clusters (Group A and Group B) to localize grid operations.

Academic Explanation (Viva Ready):

  • Divide Step: Split zone array at midpoint mid = zones.length / 2.
  • Conquer Step: Recursively partition left and right sub-arrays until length ≤ 2.
  • Combine Step: Form hierarchical regional microgrid management boundaries.

Manual Electricity Allotment & Grid Loads

Enter or adjust the Allotted Capacity (kW) and Current Active Load (kW) for each zone in the microgrid. Changes will directly update the graph, recalculate available headroom, and feed into the Python forecasting & Java load balancing engine.

Quick Presets:

💡 Grid Physics & Rules:

  • Allotted Capacity: Maximum allowable continuous transmission limit before thermal overload.
  • Available Headroom: Calculated as Max(0, Allotted Capacity - Active Load).
  • Balancing Rule: When load exceeds capacity, Java shifts excess kilowatts only to graph-connected neighbor zones.

Academic Subjects & Engineering Principles

This project is designed as an educational, multi-disciplinary engineering prototype integrating Data Structures & Algorithms (ADSA), Object-Oriented Programming (OOPJ), and Python Time-Series Analytics.

🕸️

1. ADSA (Unit 2)

Graph Theory & Divide-and-Conquer
  • Grid as a Graph: Zones modeled as vertices $V = \{Z_1, \dots, Z_5\}$ and transmission lines as edges $E$ using an Adjacency List.
  • Graph Traversal: Breadth-First Search (BFS) explores connected nodes in topological distance order to find target zones with available headroom.
  • Divide-and-Conquer: Recursively partitions the zone set into regional sub-clusters (Group A vs Group B) with base case `size ≤ 2`.
  • Grid.java • Adjacency List • BFS
☕

2. OOPJ (Java OOP)

Simulation Classes & Architecture
  • Encapsulation: Private zone attributes (`currentLoad`, `maximumCapacity`, `forecastLoad`) accessed via domain methods.
  • Domain Business Logic: Calculation methods for headroom, overload calculation, utilization rates, and thread-safe load updates.
  • Modular Simulation Engine: Separation into `Zone`, `Grid`, `LoadBalancer`, `Simulation`, and `SimpleHttpServer`.
  • Zone.java • LoadBalancer.java • Simulation.java
🐍

3. Python Analytics

Short-Term Load Demand Forecasting
  • Time-Series Forecasting: Simple Moving Average (SMA, $k=3$) with rate-of-change linear trend projection.
  • Surge Prediction: Detects impending evening/industrial surges before physical overloads occur.
  • CSV File Pipeline: Java writes `historical_load.csv` → Python reads, forecasts, & writes `forecast.csv` → Java executes load shifting.
  • forecast.py • CSV Data Exchange

🎓 How They Work Together (Pipeline):

Java OOP maintains the grid topology • ADSA D&C partitions zones into regional control domains • Java exports historical readings to CSV • Python calculates the short-term load forecast • ADSA Graph BFS discovers adjacent candidate zones with headroom • Java LoadBalancer shifts the surplus load to keep all zones stable!
